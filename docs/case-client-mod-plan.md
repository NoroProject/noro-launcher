# Клиентский мод разбора: панель дел в игре

Сегодня разбор в игре — текстовое меню (`CaseMenu`): строка кнопок `cmd:/case …`
в чате. Этого хватает, чтобы телепортироваться и заморозить, но очередь дел,
лента событий, срез чата и форма наказания живут только на сайте — модератор
разбирается в игре, а половину работы делает во втором окне.

Мод даёт экран. И закрывает то, что серверный агент не смог: **подсветку цели
через стены**. `GameBridge.glow` честно возвращает false — свечение для одного
зрителя требует подмены пакета, а ванильный `setGlowing` светит всем и выдаёт
разбор нарушителю. Клиент рисует outline локально, без микшинов на сервере.

Развилки приняты 2026-08-21 и переспрашивать их не надо.

| Развилка | Решение |
|---|---|
| Канал | Мод → лаунчер (loopback) → мастер; в игре нет токена |
| Объём v1 | Экран целиком + доказательства: инвентарь, скриншот в дело |
| Подсветка | Да, только пока дело активно и мастер это подтвердил |

## Почему через лаунчер

`/api/admin/cases/*` живёт под `AdminAuth`, а тот принимает обычный
пользовательский токен сессии — тот самый, с которым лаунчер сидит на WS.
Положить такой токен в JVM игры нельзя: любой мод из модпака прочитает env,
аргументы или файл и получит полный доступ к админке. Поэтому моду не выдаётся
ничего — он стучится к лаунчеру, лаунчер ходит к мастеру сам.

Лаунчер для этого уже готов: держит токен (`ws_client.rs`), знает права
модератора (`AuthOk { user }` несёт `UserProfile.permissions` и `roles`) и умеет
поднимать локальный слушатель (`auth/discord_oauth.rs:22`).

**Существующий сокет используем — но для пушей, не для запросов.** Протокол
лаунчера типизирован (`ClientWsMsg`/`ServerWsMsg`), это не RPC: гонять по нему
восемь ручек дел значит написать второй роутер поверх WS и корреляцию ответов
по id. Запросы остаются REST, которым уже пользуется веб; сокет приносит то,
чего у REST нет — «дело назначено тебе» и «карточка обновилась» без опроса.

```
мод ⇄ 127.0.0.1 (лаунчер) ⇄ мастер
      mod_link: типизированные кадры   HTTPS: токен сессии
                                       WS: уже открыт
```

Без права мастер отвечает 403, и это единственная проверка, которой стоит верить.

Рукопожатие: при запуске игры лаунчер поднимает слушатель на `127.0.0.1:0` и
кладёт в каталог инстанса `noro-bridge.json` — порт и одноразовый ключ. Файл
уходит в `unmanaged_paths`, чтобы сверка целостности не считала его лишним.
Игра закрылась — слушатель гасится, ключ протухает.

## Канал `mod_link`: как у фронта с беком

Соблазн сделать прозрачный прокси — «пробрасываем `/api/admin/cases/*`, мод сам
разберёт JSON» — надо отклонить. Тогда мод знает URL админки, форму ответов и
порядок вызовов, а обновляется он отдельно от лаунчера: любая правка ручки
ломает клиент, который уже у людей.

Берём образец, который в проекте работает — `crates/bridge`. Фронт лаунчера не
знает про HTTP мастера вовсе: он шлёт намерение (`OpenServer { server_id }`) и
рисует состояние, которое ему прислали (`BuildStateChanged`). Мод получает ровно
такой же договор, просто через провод.

`crates/mod_link` — два serde-enum рядом, как `MessageToBackend` /
`MessageToFrontend`:

- **`ToLauncher`** — намерения: `Claim`, `Release`, `Resolve`, `AddNote`,
  `Punish`, `RequestChat`, `RequestInventory`, `Attach`, `Quote`, `Lookup`;
- **`ToMod`** — состояние: `Ready { permissions, username, locale }`, `Queue`,
  `Case`, `Dossier`, `ChatSlice`, `Inventory`, `Rejected`, `Notice`.

Мод не «запрашивает и ждёт ответ» — он подписан. Пришёл `CaseUpdated` с мастера
по уже открытому WS, лаунчер сходил за карточкой и прислал `Case`. Поэтому в
протоколе нет ни request-id, ни корреляции ответов: их нет и у фронта.

На стороне Java это ложится один в один, потому что клиент — Java 21:

```java
sealed interface ToMod permits Ready, Queue, Case, Dossier, /* … */ {}
record Case(UUID id, CaseView view) implements ToMod {}

switch (frame) {
    case Case c  -> screen.show(c.view());
    case Queue q -> screen.show(q.cases());
    // забыл кадр — не компилируется, ровно как незакрытый match
}
```

Транспорт — один WebSocket на loopback: пара mpsc в проводном виде, в обе
стороны сразу. Разбор — Gson, который уже едет с игрой (агент берёт его так же,
`compileOnly`); полиморфизм закрывается картой `type → класс` на два десятка
строк, без плоского record со всеми полями всех кадров, как в `LinkFrame`.

Три отличия от внутрипроцессного bridge, которые нельзя проигнорировать:

1. **Версии расходятся.** Мод приезжает со сборкой, лаунчер обновляется сам.
   Первый кадр — `Hello { key, protocol }`; незнакомые кадры логируются и
   пропускаются, новые поля идут с `#[serde(default)]` — тем же приёмом, что
   спасал `ClientWsMsg` при выпуске новых полей.
2. **`ModalAction` по проводу не передать** — он держится на `Arc`. Долгих
   операций у мода почти нет: инвентарь и срез чата асинхронны по природе и
   приезжают пушем, а всё остальное мгновенно. Где нужен отказ — `Rejected`,
   где нужно сказать словами — `Notice` ключом перевода, как у фронта.
3. **Канал открыт наружу процесса.** Ключ из файла рукопожатия обязателен:
   чужая веб-страница может открыть `ws://127.0.0.1:port` — CORS на WebSocket не
   распространяется, — но прочитать файл в каталоге инстанса она не может.

Побочная выгода, ради которой это стоит делать именно так: состояние дел живёт
в беке лаунчера одним store, а UI над ним — два. Вкладка «Дела» в самом лаунчере
получается почти бесплатно, и модератору не нужен браузер, даже когда игра
закрыта.

**Действия в мире идут командами.** Мод шлёт те же `/case tp target`,
`/case watch`, `/case freeze`, что и кнопки в чате: серверный агент не трогаем
вообще, ни одной из 80 сборок. Право проверяет мастер, как и раньше.

## Что добавится на мастере

1. `ServerWsMsg::CaseUpdated { case_id }` — один кадр без данных: мод дёрнет
   карточку сам. Шлётся модератору, за которым замок, на каждое событие дела.
   Заодно избавляет карточку на сайте от опроса раз в 5 секунд.
2. `POST /api/admin/cases/{id}/attachments` — скриншот в дело. Файл ложится в
   CAS (`state.files.put_bytes`, как капы), в ленту падает событие
   `kind = "screenshot"` с `file_url`. Право — `noro.mod.cases.claim`: кто ведёт
   дело, тот и прикладывает.
3. `case_events.kind` пополняется `screenshot`; ключи перевода — в обе локали.

Ручка «мои права» не нужна: профиль уже у лаунчера.

## Что добавится в лаунчере

`crates/mod_link/` — протокол: два enum и ничего больше, по образцу
`crates/bridge/src/message.rs`.

`crates/backend/src/mod_link/` — слушатель на loopback, файл рукопожатия, разбор
кадров и `case_store`: кэш очереди и открытой карточки. Store обновляется по
`CaseUpdated` с мастера и рассылается подписчикам — сейчас моду, потом и вкладке
в лаунчере.

Игра не запущена — кадр просто некуда класть, и это нормально: store переживёт
до следующего подключения.

## Клиентский мод

`agent/client/` — NeoForge 1.21.1, ровно под опубликованную сборку. Препроцессор
и матрица версий сюда не приезжают: клиент один. Модуль отдельный, потому что с
серверным агентом у него нет общего кода — только общий словарь событий.

Экраны:

- **очередь** — цель, число жалоб, приоритет, кто ведёт, сколько висит;
- **карточка** — лента, срез чата с фильтром каналов, действия. Заметка пишется
  многострочно, а не одной командой;
- **наказание** — форма с вилками свода, `rule_code` подставлен из дела;
- **инвентарь** — снимок цели контейнером, а не списком строк;
- **оверлей разбора** — цель, таймер, действия поверх игры, без захвата курсора.

Хоткей открывает панель, только если в правах есть `noro.mod.cases.view`; кнопки
рисуются по `noro.mod.cases.claim/resolve/chat/inventory/watch/client`. Это
удобство, а не защита: решает всё равно мастер.

## Как это должно ощущаться

Перенести карточку с сайта в GUI недостаточно: на сайте модератор сидит мышкой в
браузере, а в игре он уже стоит рядом с целью и держит руки на движении. Экономит
время не «где посмотреть», а «сколько действий до решения». Отсюда правила.

**Взять дело — одно действие.** Из очереди Enter: замок, вход в режим, ваниш и
телепорт к месту происходят разом. Не «взял → закрыл окно → набрал `/case tp`».

**Оверлей не отнимает управление.** Пока идёт наблюдение, панель — это HUD сбоку:
живой чат цели, её статус, таймер дела. Полноэкранный GUI открывается отдельной
клавишей и только когда действительно нужен: открытый экран в мультиплеере значит
«я не двигаюсь», и это не то состояние, в котором ловят читера.

**Действия — радиальным меню.** Зажал клавишу, повёл мышью, отпустил: тп к цели,
назад, ваниш, заморозка, слежка, инвентарь. Список кнопок проигрывает колесу,
когда действие повторяется десятки раз за смену.

**Наведение показывает досье.** Смотришь на игрока — плашка: ник, роль, сколько
дел с `confirmed`, активные муты и варны, дата первого входа. Это тот же вопрос
«он новичок или у него третий бан за то же», который сейчас требует ухода на сайт.

**Сообщение в чате кликабельно.** Правый клик по строке чата — «в дело»: завести
новое или добавить к открытому. Модератор, который видел мат своими глазами, не
должен ждать жалобы и искать окно во времени.

При этом **клиент не источник доказательств — он лишь указывает на них**. Мод шлёт
отправителя, время и хеш текста, а в дело едет строка из `ChatRing` агента.
Подделать переписку правым кликом невозможно, и это тот же принцип, что с правами.

**Цитата становится причиной.** Выбрал сообщение в срезе — оно подставляется в
причину наказания и прикрепляется к делу. Копировать руками ничего не нужно.

**Отмена на месте.** Ошибочный бан снимается кнопкой в ленте, пока событие
свежее. Сейчас за этим идут в админку, а исправлять свою же опечатку страшно
ровно настолько, насколько это долго.

**Новое дело — тост, а не чат.** Уголок экрана, клавиша «взять». Спам в чат
модератор перестаёт читать на второй день. В настройках — тише во время игры.

**Ничего не выдаёт разбор.** Панель не издаёт звуков, не тратит слот интерфейса,
не мигает частицами: модератор в ванише должен оставаться невидимым и на экране.

## Маршруты, а не один универсальный экран

Дела делятся на три вида, и каждый требует своего:

- **чат** (самое частое) — телепорт не нужен вовсе: открыл дело, увидел срез,
  щёлкнул сообщение, выдал мут. Три действия, из мира выходить не пришлось;
- **чит** — слежка. Здесь мод даёт то, чего не даст ни сайт, ни глаза: числа.
  Скорость, высота над землёй, скорость копания, клики в секунду, углы поворота
  головы по тикам. «Развернулся на 178° за два тика четырнадцать раз» — это
  запись в деле, а не ощущение. Показания приблизительные, клиент видит цель
  через трекинг: они помогают смотреть, но вердикт выносит человек;
- **гриф** — координаты, телепорт к месту, снимок инвентаря, скриншот в дело.

Скриншот — клавиша в оверлее: кадр уходит вложением, минуя папку `screenshots/`.
Killaura скриншотом не докажешь, а «стоял в чужом доме с чужим сундуком» — вполне.
Телепорт к цели и начало слежки снимают кадр сами: контекст в деле появляется
без напоминаний.

Подсветка включается, когда мастер подтвердил активное дело за этим модератором,
и гаснет вместе с ним. Мод рисует только тех сущностей, которые клиент и так
получил от сервера, — новых позиций он не запрашивает.

Язык интерфейса — обычные клиентские `lang`-файлы: мод показывает то, на чём
стоит игра, `ru` и `en`, как у агента.

## Раздача

Опциональный мод с правом — механизм уже есть: `noro.optional.<server>.<mod>`
(`schema/src/permissions.rs:203`), а сверка целостности удаляет чужим лишний
файл как `ForbiddenOptionalMod`. Модератор видит панель в списке модов, остальные
не видят ничего.

Прятать при этом нечего: в jar лежит рабочий ESP-код, и тот, кто его
декомпилирует, получит подсветку игроков без всяких прав. Это не аргумент против
— готовых ESP хватает и без нас, — но повод не тащить в мод ничего сверх
подсветки участников дела.

## Границы

**Мод не даёт возможностей, которых нет из чата и с сайта.** Иначе «опциональный»
перестаёт быть правдой: модератор без мода оказывается модератором второго сорта,
и панель становится обязательной. Всё, что появляется на экране, должно иметь
путь через `/case …` или `/admin/cases`.

Мод — экран, а не носитель прав. Клиент подделывается, jar декомпилируется;
любая проверка внутри него — украшение. Мастер отвечает 403 — панель показывает
отказ, и это единственная линия.

## Порядок

1. мастер: `CaseUpdated`, вложения, ключи перевода;
2. `mod_link`: протокол, слушатель, рукопожатие, `case_store`;
3. мод: очередь и карточка на чтение — уже полезно;
4. мод: взять дело одним действием, радиальное меню, наказание с цитатой;
5. мод: оверлей слежки, подсветка, скриншот, инвентарь;
6. мод: досье при наведении, клик по сообщению в чате, телеметрия слежки;
7. сайт переезжает с опроса на `CaseUpdated` — попутная уборка.

Порядок такой, потому что первые три шага уже дают модератору рабочий инструмент,
а всё, что делает его быстрым, опирается на них и проверяется на живом разборе.

Выкладка обычная: релиз мастера и лаунчера, мод заливается опциональным в сборку
(см. [agents.md](./agents.md) про агента — его здесь не трогаем).
