# Фаза D — моды на игровом сервере

Статус: **сделано**. Дата: 2026-08-09.

Общий план — в [README.md](./README.md), файлы — [phase-c.md](./phase-c.md).

## Что появилось

Цель `game_server` в установке модов (объявленная ещё в фазе A) стала настоящей:
`wrapper::ops::install_mod` больше не заглушка.

### Враппер (Java)

| Файл | Роль |
|---|---|
| `ServerMods.java` | Скачать по ссылке, сверить sha1, положить в каталог модов |
| `Sha1.java` | Общая читалка хеша; `AgentInstaller` теперь пользуется ей же |

Операция `mod_install` в `ControlOps`. Ответ: `{path, changed, size, restart_required}`.

### Мастер

`Op::ModList` удалён, не дожив до реализации: список установленного — это тот же
`FsList` по каталогу модов, а имя каталога мастер знает из платформы в `hello`
(`wrapper::ops::mod_dir`).

### Веб

| Файл | Роль |
|---|---|
| `components/gameserver/Mods.vue` | Вкладка Mods: список jar'ов, удаление, вход в каталог |
| `components/mods/TargetPicker.vue` | Новый проп `gameServerId` — цель отмечается сразу |
| `components/mods/Browser.vue` | Пробрасывает контекст дальше |
| `pages/admin/mods.vue` | Читает `?server=` и `?gs=` из query |

Кнопка «Add from catalog» ведёт на `/admin/mods?server=<pack>&gs=<id>` — браузер
открывается с уже отмеченной целью.

## Решения, которые стоит знать

**Файл качает враппер, а не мастер по сокету.** Он уже лежит в сторе мастера,
адресуется своим sha1 и раздаётся обычным HTTP с докачкой. Гонять тот же jar
через WebSocket ради того же результата смысла нет.

**Подпись мода не проверяется — в отличие от jar'а агента.** Мод выбрал
администратор из каталога, мастер его не подписывал и подписать не может.
Гарантия здесь одна и настоящая: sha1 совпал с тем, что мастер положил в стор.

**Установка идемпотентна**: если файл с тем же sha1 уже лежит, враппер отвечает
`changed: false` и ничего не трогает.

**`restart_required: true` всегда.** Лоадер читает каталог модов один раз при
старте: без рестарта файл на диске есть, а в игре его нет.

**Каталог зависит от платформы.** Paper и прокси — `plugins`, лоадеры — `mods`.
Решает мастер по платформе из `hello`; веб повторяет ту же таблицу, чтобы знать,
какой каталог показывать.

**Отдельной операции «список модов» нет.** Это был бы `fs_list` под другим
именем.

## Проверено вживую

Локальный мастер + фальшивый враппер, реализующий `mod_install` как настоящий
(скачать → сверить sha1 → положить), каталог `mods` в реальном временном
каталоге (`scratchpad/verify_d.py`):

1. Один запрос установки в сборку **и** в игровой сервер — обе цели `ok`.
2. Jar (1 574 596 байт) лёг на диск сервера; sha1 сверен, иначе установка упала бы.
3. `fs_list` по каталогу модов видит установленный файл.
4. Повторная установка того же — `ok`, без перезаписи.
5. При отключённом враппере — честная ошибка в строке отчёта, установка в сборку
   при этом проходит.
6. Выбор каталога по платформе проверен обеими ветками: с `platform: paper` файл
   ушёл в `plugins/`, с `fabric` — в `mods/`.
