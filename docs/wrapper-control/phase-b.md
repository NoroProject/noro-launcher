# Фаза B — канал управления, консоль, питание

Статус: **сделано**. Дата: 2026-08-09.

Общий план — в [README.md](./README.md), предыдущая фаза — [phase-a.md](./phase-a.md).

## Что было до

Враппер одноразовый: `main` ставил агент, запускал сервер, ждал его выхода и
завершался (`System.exit`). Обратного канала не было вообще — мастер знал об
игровом сервере только из HTTP-heartbeat агента, который живёт внутри сервера и
поднимается уже после старта.

## Что стало

### Протокол

WebSocket, соединение открывает **враппер**: `GET /api/agent/ws`, авторизация —
`Authorization: Bearer <секрет игрового сервера>`, тот же `AgentAuth`, что у
остального агентского API. Из секрета мастер берёт, о каком сервере речь.

Кадры — JSON с полем `type`.

Враппер → мастер:

| type | поля |
|---|---|
| `hello` | `platform`, `mc_version`, `wrapper_version`, `server_dir`, `status` |
| `status` | `running`, `ready`, `uptime_secs`, `exit_code` |
| `console` | `line` |
| `reply` | `id`, `ok`, `data` \| `error` |

Мастер → враппер: `{"type":"request","id":N,"op":"...","args":{...}}`.

`hello` обязан быть первым кадром — иначе мастер рвёт соединение: «подключён
неизвестно кто» админке показывать нечего.

### Мастер

`crates/master/src/wrapper/`:

| Файл | Роль |
|---|---|
| `proto.rs` | `Op` (все операции всех фаз), `WrapperInfo`, `WrapperStatus`, `FromWrapper`, `WrapperState` |
| `hub.rs` | `WrapperHub` — реестр по `game_server_id`; `Conn::call` с корреляцией по `id` и таймаутом |
| `session.rs` | axum-хендлер сокета: hello → регистрация → цикл чтения |
| `ops.rs` | Типизированные обёртки: `power`, `command`, `install_mod`, `mod_dir` |
| `hub_tests.rs` | 6 тестов: форма кадра, ответ, ошибка, обрыв, переподключение, кольцевой буфер |

Таймаут вызова зависит от операции (`Op::timeout`): бэкап — 900 с, питание —
180 с, остальное — 30 с. Один короткий таймаут рвал бы и `stop`, и архив мира.

Админ-API (`api/admin/wrapper.rs`, право **`noro.admin.wrapper`**):

```
GET  /api/admin/game-servers/{id}/wrapper                  → WrapperState
POST /api/admin/game-servers/{id}/wrapper/power            {action}
POST /api/admin/game-servers/{id}/wrapper/command          {line}
GET  /api/admin/game-servers/{id}/wrapper/console          → хвост буфера
GET  /api/admin/game-servers/{id}/wrapper/console/stream   → SSE
```

`AppState.wrappers: WrapperHub`.

### Враппер (Java)

| Файл | Роль |
|---|---|
| `Main.java` | Установка агента → супервизор → канал → stdin-консоль (она же держит процесс) |
| `Supervisor.java` | start/stop/restart/kill, статус, рассылка консоли и статуса |
| `Lifecycle.java` | Однопоточный исполнитель переходов состояния |
| `ExitWatcher.java` | Ждёт выхода, решает про автоподъём (защита от crash-loop) |
| `ServerProcess.java` | Ручка над процессом: запуск, ввод, вывод, остановка |
| `ControlLink.java` | WebSocket с реконнектом (backoff 2→60 с), периодический статус |
| `Outbox.java` | Очередь исходящих, один поток отправки, потолок 2000 кадров |
| `RequestPump.java` | Разбор запросов, исполнение в своих потоках, ответы |
| `ControlFrames.java` | Сборка кадров |
| `ControlOps.java` | Диспетчер операций |
| `Threads.java` | Фабрика демон-потоков |

Новые ключи `noro-wrapper.properties`: `autostart` (по умолчанию `true`),
`restart-on-crash` (`true`).

## Решения, которые стоит знать

**Один поток на переходы состояния, а не блокировка.** Остановка ждёт, пока
сервер сохранится и выйдет; наблюдатель за выходом в этот же момент хочет
объявить результат. На общем мониторе они встали бы друг против друга.

**Автоподъём не трогает crash-loop.** Сервер, проживший меньше 60 секунд, не
«упал» — он не стартует, и поднимать его бесполезно.

**Консоль — SSE, а не WebSocket.** Токен админки уходит мастеру заголовком
`Authorization`, а браузерный `WebSocket` заголовки ставить не умеет. Класть
токен в query-строку, где он осядет в логах прокси, ради одностороннего потока
текста не стоит.

**Отставший читатель консоли пропускает строки, а не рвёт поток**
(`broadcast::error::RecvError::Lagged` → `continue`).

**Переподключение вытесняет прежнее соединение**, но `unregister` снимает
регистрацию только если она всё ещё своя (`Arc::ptr_eq`) — иначе умирающий сокет
снёс бы только что подключившийся.

**Кто отмечает сервер живым.** Пока `running && !ready`, это делает статус от
враппера: агент внутри ещё не поднялся, а мастер считает сервер мёртвым через 90
секунд. Как только `ready` — мастер замолкает, дальше heartbeat шлёт агент со
своим настоящим онлайном. Старый boot-heartbeat из `Main` за ненадобностью
удалён.

**Право отдельное.** `noro.admin.wrapper`, не `noro.admin.servers`: запись файла
плюс рестарт — это фактически рут на игровой машине.

## Проверено вживую

Поднят локальный мастер (`noro-launcher-pg` + `./target/debug/noro-master`), к
нему подключён фальшивый враппер (рукописный WebSocket-клиент на Python,
`scratchpad/fakewrapper.py`). Результат:

1. До подключения — `connected: false`.
2. После `hello` — `connected: true`, платформа и каталог видны.
3. Строки консоли доходят до буфера мастера.
4. `POST power {action:"restart"}` дошёл до враппера как
   `{"op":"power","args":{"action":"restart"}}`, ответ вернулся вызывающему.
5. `{"action":"explode"}` отбит с 400.
6. `status ready:true` отражается в состоянии.
7. SSE-поток отдал строку, отправленную после подписки.
8. После обрыва сокета — `connected: false`.

Заодно проверена установка модов из фазы A на живой БД: Modrinth-мод уехал в
сборку с правильным автором (`jellysquid3`), `all_servers` развернулся в игровой
сервер и честно отчитался «враппер не подключён», пустой список целей отбит.

**Найден и починен баг фазы A:** имя файла из прямой ссылки оставалось
процентно-закодированным (`sodium%2Bmc1.21.1.jar`). Добавлен
`catalog::resolve::safe_filename` — декодирует и срезает разделители пути; на
него 4 теста (`resolve_tests.rs`). Применён ко всем трём источникам.

**`CURSEFORGE_API_KEY` в `.env` невалиден** — CurseForge отдаёт 403 и на прямой
запрос curl'ом, мимо нашего кода. Ветка CurseForge поэтому вживую не проверена;
видно только, что деградация работает: в режиме `all` выдача Modrinth приходит, а
CurseForge попадает в `failed`.
