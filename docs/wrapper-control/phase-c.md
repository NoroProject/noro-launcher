### Мастер

`wrapper/fs_ops.rs` — обёртки над `WrapperHub::call` плюс `fan_out` (одна
операция на несколько серверов, отчёт построчно).

`api/admin/wrapper_fs.rs`, всё под **`noro.admin.wrapper`**:

```
GET    /api/admin/game-servers/{id}/fs?path=        → {path, entries[]}
DELETE /api/admin/game-servers/{id}/fs?path=
GET    /api/admin/game-servers/{id}/fs/file?path=   → {path, content}
PUT    /api/admin/game-servers/{id}/fs/file         {path, content}
POST   /api/admin/game-servers/{id}/fs/mkdir        {path}
POST   /api/admin/game-servers/{id}/fs/apply        {path, content, targets[]}
```

## Решения, которые стоит знать

**Пути проверяет враппер, мастер их не трогает.** У враппера есть настоящая
файловая система; повторять проверку на мастере значит однажды развести две
реализации.

**Песочница — не защита от администратора.** Тот, кто может положить jar в
`plugins/` и перезапустить сервер, уже исполняет код на машине. Это защита от
выхода за пределы каталога: `../..`, абсолютный путь, симлинк наружу. Плюс одно
настоящее ограничение — `noro-wrapper.properties` не читается и не пишется: в нём
секрет игрового сервера открытым текстом.

**Корень канонизируется в конструкторе.** На macOS `/var` сам по себе симлинк на
`/private/var`; сравнение «настоящего» пути с ненастоящим корнем объявляло бы
побегом любой путь внутри каталога. Тесты поймали ровно это — три падения из
шести до фикса.

**Запись через временный файл и `move`.** Оборванная запись не должна оставить
конфиг наполовину переписанным: сервер такой не переживёт.

**Бинарное не открывается как текст.** Декодер UTF-8 в строгом режиме: отдать
мусор хуже, чем отказать. Потолок текстового файла — 1 МиБ.

**Веер последовательный, а не пачкой.** Если конфиг ломает сервер, лучше увидеть
это на первом, чем разослать поломку на все сразу. Исходный сервер из списка
целей вычитается — дважды писать незачем.

**Удаление каталога рекурсивное**, снизу вверх. Подтверждение — на стороне веба.

## Проверено вживую

Локальный мастер + два фальшивых враппера с настоящими временными каталогами
(`scratchpad/verify_c.py`):

1. `list` — каталоги и файлы.
2. `read` — содержимое `server.properties`.
3. `write` — файл появился на диске с нужным содержимым.
4. `apply` на два сервера — оба получили новый `motd`; исходный сервер, переданный
   и в `targets`, посчитан один раз (2 строки отчёта, не 3).
5. `mkdir`, 6. `delete` — сработали.
7. Побег `../../../etc/passwd` отбит 400-м.
8. При отключённом втором сервере отчёт честно раздельный: первый `ok`, второй
   «враппер не подключён».

Java-сторона (песочница и файловые операции) закрыта 12 юнит-тестами, всего в
модуле `wrapper` 21 тест — все зелёные.
