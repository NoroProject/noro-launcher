# Серверные агенты и ServerWrapper

Спека для Java-части. Мастер-сторона готова и проверена вживую. Агенты и
враппер написаны и собираются; что осталось непроверенным — отмечено ниже.

## Что уже работает на мастере

### Авторизация агента

У каждого игрового сервера свой секрет вида `noroagent_<64 hex>`. В БД лежит
только его sha256 (`game_servers.token_hash`), plaintext админ видит один раз
при выдаче в админке. Заголовок: `Authorization: Bearer <secret>`.

Админ-токен на `/api/agent/*` не работает и не должен: секрет лежит на игровой
машине, а к ней есть доступ у тех, кто сервером управляет. Проверено — 401 в
обе стороны.

`server_id` мастер берёт **из секрета**, агент его не передаёт. Подменить,
за какой сервер отчитываешься, нельзя.

### `GET /api/agent/players/{mc_uuid}`

```json
{
  "uuid": "95bf010b-8e9f-55d5-8f1c-766c624ab7e0",
  "username": "dalynkaa",
  "banned": false,
  "allowed": true,
  "roles": [
    { "name": "admin", "display_name": "Админ", "lp_group": "admin",
      "color": "#ff8c82", "icon": "★", "sort_order": 100 }
  ],
  "skin_url": "http://…/api/textures/default-skin",
  "cape_url": null,
  "lp_groups": ["admin", "player"]
}
```

- `roles` отсортированы по `sort_order` убыванием.
- `lp_group` может быть `null` — такая роль в игру не проецируется.
- `lp_groups` — готовый список в порядке важности, повторять отбор не надо.
- `skin_url` есть всегда: свой скин игрока либо общий Стив.
- 404, если игрока нет в базе мастера.

**`allowed` считает мастер**, агент только исполняет. В него уже входит бан и
право `noro.server.<id>.join` для ограниченных сборок. Дублировать эти правила
в трёх реализациях агента нельзя — разъедутся.

### `POST /api/agent/heartbeat`

```json
{ "online": 12, "max_players": 60, "version": "Paper 1.21.1" }
```

Отвечает `{"ok": true}`. Слать раз в 30 секунд: сервер считается живым, если
heartbeat приходил меньше 90 секунд назад (`LIVE_WINDOW_SECS`).

Мастер складывает онлайн **только по бэкендам**. Прокси и бэкенды видят одних
и тех же игроков — если сложить всё, получится вдвое. Прокси идёт в зачёт,
только когда бэкендов не завели вовсе.

### `GET /api/agent/artifact?platform=paper&mc=1.21.1`

Откуда ServerWrapper берёт jar агента. Авторизация — тем же секретом агента.

```json
{
  "platform": "paper",
  "mc_version": "1.21.1",
  "sha1": "da39a3ee…",
  "size": 27106,
  "url": "http://…/files/da39a3ee…",
  "signature": "<ed25519, hex>"
}
```

Мастер ищет файл в `{NORO_DATA_DIR}/agents/{platform}-{mc}.jar`, кладёт его в
общий content-addressed стор и отдаёт ссылку на обычный `/files/{sha1}` — с
Range и ETag, как у всех остальных файлов. 404, если такой агент не собран.

Подпись считается по этому же JSON с **пустым** `signature`, тем же ключом, что
подписывает манифесты сборок. Она покрывает `sha1`, поэтому подтверждает и
содержимое: враппер проверяет подпись, потом сверяет хеш скачанного.

**Порядок полей — часть контракта.** Serde сериализует поля в порядке
объявления, и Java обязана собрать те же байты. Обе стороны прибиты тестами:
`signing_bytes_are_stable` в `agent_artifact.rs` и `ArtifactSignatureTest` во
враппере проверяют одну и ту же строку.

### Типы игровых серверов

В админке у каждого сервера сборки есть тип: `proxy` (точка входа, куда
коннектится игрок) или `server` (бэкенд с агентом). Оба шлют heartbeat, но
в сумму идут бэкенды.

### Yggdrasil

Корень API: `{master_url}/api/yggdrasil` — именно его надо отдавать
authlib-injector'у в `-javaagent:authlib-injector.jar=<URL>`, не корень мастера.
Пути внутри: `authserver/*`, `sessionserver/session/minecraft/*`,
`api/profiles/minecraft`.

## Что построить

```
agent/
├── core/                     MasterClient, AgentConfig, AccessGate, RoleSync,
│                             GroupPrefix, PrefixFormat, HeartbeatTask
├── paper/                    plugin.yml, AsyncPlayerPreLoginEvent
├── mod/                      Fabric и NeoForge из одного исходника
│   ├── src/main/java/        AgentRuntime + точки входа под //#if
│   └── versions/             1.21.1-fabric, 1.21.1-neoforge,
│                             1.21.4-fabric, 1.21.4-neoforge
└── wrapper/                  ServerWrapper — установщик и супервизор
```

`core` не должен зависеть ни от одного игрового API: HTTP, конфиг, модель
данных и логика раскладки ролей в группы живут только там. Платформенные
модули — тонкие адаптеры событий.

### Функции агента

**1. Роли → группы LuckPerms.** Мастер в LuckPerms не пишет и писать не будет.
Агент берёт `lp_groups` и приводит игрока к этому списку через LuckPerms API
(`LuckPermsProvider`, платформенно-независимый). Важно: **снимать группы,
которых в списке больше нет**, а не только добавлять. Иначе снятая на сайте
роль останется в игре навсегда.

**2. Префикс группы.** Иконка роли в цвете роли. `#rrggbb` →
`§x§r§r§g§g§b§b`, дальше `icon`, потом `§r`. Ставится как meta prefix с весом
= `sort_order`. Роли без `icon` префикса не получают.

**3. Контроль доступа.** `allowed == false` → не пускать. На Paper это
`AsyncPlayerPreLoginEvent` (до входа в мир, а не кик после). В прокси-топологии
проверку логичнее делать на прокси, чтобы игрок вообще не доходил до бэкенда.

**4. Онлайн.** Heartbeat раз в 30 секунд, плюс сразу при старте.

**5. Права модам.** Мастер отдаёт `permissions` в профиле игрока — обычные узлы
и `prefix.<вес>.<значение>`, — а агент отвечает ими на вопросы игры. Семантика
wildcard общая с мастером: `*` подходит ко всему, `foo.*` — к `foo` и
`foo.<что-угодно>`, остальное точно. Одна реализация на все платформы —
`PermissionSet` в `core`, и её тест повторяет тест `permission_matches` в
`crates/schema/src/permissions.rs` случай в случай.

**6. Плейсхолдеры.** Профиль мастера доступен чужим плагинам и модам: TAB,
чат-форматтерам, скорбордам. Значения считает один класс на все платформы —
`PlaceholderValues` в `core`; разведи это по реализациям, и `%noro_role%` начал
бы означать разное на разных ядрах.

### Плейсхолдеры

Профиль кладётся в `ProfileCache` на входе и снимается на выходе: плейсхолдер
дёргают на каждую перерисовку таба, и второй запрос к мастеру там недопустим.
Офлайн-игрок значений не имеет — показывать данные неизвестной свежести хуже,
чем промолчать.

| Ключ | Значение |
| --- | --- |
| `username`, `uuid` | как их знает мастер |
| `banned`, `allowed` | `true` / `false` |
| `prefix` | готовый префикс: `§x§f§f§8§c§8§2★§r` |
| `prefix_plain` | та же иконка без цвета |
| `role`, `role_name` | `display_name` и `name` старшей роли |
| `role_color`, `role_color_legacy` | `#ff8c82` и `§x§f§f§8§c§8§2` |
| `role_icon`, `role_sort` | иконка и вес старшей роли |
| `roles` | названия всех ролей через запятую, по убыванию веса |
| `roles_icons` | иконки всех ролей подряд, каждая в своём цвете |
| `role_count`, `group_count`, `permission_count` | размеры списков |
| `group`, `groups` | группы LuckPerms в порядке важности |
| `skin_url`, `cape_url` | ссылки из профиля |
| `has_role_<имя>`, `has_group_<имя>` | `true` / `false` |
| `permission_<узел>` | `true` / `false`, wildcard как у мастера |

Роль для показа и роль для префикса — разные. `role*` берут старшую по
`sort_order`, а `prefix` — старшую **из тех, у кого есть иконка**: у старшей
роли иконки может не быть, и в игре тогда видна иконка следующей. То же правило,
что у LuckPerms с весами префиксов.

Неизвестный ключ остаётся неразобранным, а не превращается в пустую строку:
`%papi_something%` должен достаться тому, чей он на самом деле.

**Paper** — через PlaceholderAPI, `%noro_<ключ>%`, хвост пишется слитно:
`%noro_has_role_admin%`. Расширение объявлено `persist()`, иначе `/papi reload`
снимал бы его до перезапуска сервера.

**Fabric** — через [Text Placeholder API](https://placeholders.pb4.eu/),
`%noro:<ключ>%`, хвост идёт аргументом: `%noro:has_role admin%`.

**Forge и NeoForge остаются без плейсхолдеров.** Text Placeholder API — мод
только под Fabric и Quilt, аналога под Forge-подобные лоадеры не существует, а
PlaceholderAPI — плагин Bukkit и на модовых серверах не работает. Поэтому весь
`PlaceholderBridge` закрыт `//#if FABRIC==1`.

### `NoroAgentApi` — для чужих модов и плагинов

Там, где плейсхолдеров нет (Forge, NeoForge) либо где нужен не текст, а сами
данные, профиль отдаёт `NoroAgentApi` в `core`:

| Метод | Отдаёт |
| --- | --- |
| `profile(uuid)` | весь `PlayerProfile` |
| `prefixRole(uuid)` | роль, чей префикс виден в игре |
| `topRole(uuid)` | старшая роль по `sort_order` |
| `value(uuid, key)` | значение по ключу плейсхолдера, строкой |

Разница с LuckPerms существенная, если у мода своя отрисовка: там префикс лежит
одной legacy-строкой `§x§f§f§8§c§8§2★§r`, а здесь `RoleInfo` отдаёт `#ff8c82` в
`color()` и `★` в `icon()` **раздельно** — hex не надо восстанавливать из
`§x`-кодировки.

`value()` возвращает строки и принимает строки, поэтому годится для вызова через
reflection: мод, не желающий зависеть от классов агента, обходится
`Class.forName("dev.noro.agent.core.NoroAgentApi")`.

### Каталог узлов: заявка вместо реестра

Реестр узлов прав есть не везде. На Paper их перечисляет `PluginManager`, на Forge
и NeoForge — `PermissionGatherEvent`, а на Fabric такого реестра нет ни у одного
мода. Вдобавок `PermissionGatherEvent` приходит **раньше**, чем большинство модов
успевает прочитать свой конфиг: `ServerLifecycleHooks.handleServerStarting` зовёт
`PermissionAPI.initializePermissionAPI()` до того, как разошлёт
`ServerStartingEvent`. Узлы, чьи имена зависят от конфига, туда просто не успевают.

Поэтому каталог не только собирается с платформы, но и принимает заявки:

```java
NoroAgentApi.registerPermissionNodes(List.of("nbitchat.chat.local", "nbitchat.pm"));
```

Порядок вызовов значения не имеет. Пришедшее до того, как платформенная часть
подключила отправку, ждёт в наборе; пришедшее после — уходит сразу. Повторная
заявка тем же списком отправки не вызывает, поэтому перезагружаемым плагинам
можно звать это на каждый `reload`.

Принимает и отдаёт только типы JDK — годится для reflection наравне с `value()`.

Кэш живёт в самом `NoroAgentApi`, а платформенные части берут его через
`cache()`. Отдельная фаза установки дала бы окно, где API уже виден, но ещё
пуст, и звонящий не отличил бы это от «игрок офлайн».

### Права: тайминг решает всё

LuckPerms на Forge грузит игрока на `PlayerLoggedInEvent`, а тот наступает
**после** `PlayerList.sendPlayerPermissionLevel` → `Commands.sendCommands`, где
права уже читают. Результат — `IllegalStateException: Capability has not been
initialised` и кик с «Invalid player data». Повторять эту ошибку нельзя, поэтому
агент снимает права на `PlayerNegotiationEvent`: его `enqueueWork` логин
дожидается, и к моменту сборки дерева команд права на месте.

Побочный выигрыш: решение о доступе снимается там же, и вход в мир второй раз к
мастеру не ходит. На Fabric такой фазы нет — там всё осталось как было.

### Регистрации обработчика мало

Forge и NeoForge выбирают обработчик прав **по конфигу**, а не по факту
регистрации: `permissionHandler` в `config/neoforge-server.toml`
(`config/forge-server.toml` на Forge) по умолчанию указывает на встроенный.
Пока там не написано `permissionHandler = "noro:agent"`, права мастера
игнорируются молча. Агент проверяет это на старте и пишет в лог, что делать, —
иначе причину пришлось бы искать вслепую.

Права других типов, кроме булевых, мастер не описывает, и отсутствие права —
не запрет, а «нечего сказать»: в обоих случаях спрашивается дефолт узла. Иначе
оператор и консоль потеряли бы всё, что им даёт уровень прав.

На Paper то же самое делается через `PermissionAttachment` — вешается на входе,
снимается на выходе. Bukkit шаблоны сам не раскрывает, поэтому `foo.*`
разворачивается по зарегистрированным на сервере правам; большего списка там и
не существует.

### `POST /api/agent/nodes`

Каталог узлов, которые агент видит на своём сервере, уходит мастеру один раз за
старт: на модах — из `PermissionGatherEvent.Nodes`, на Paper — из
`PluginManager.getPermissions()`. Покрытие неполное по природе: сюда попадают
только те моды и плагины, которые регистрируют узлы через API. Кто проверяет
права строкой напрямую, в каталоге не появится, и обещать обратное нельзя.

### Решения, принятые при реализации

Спека их не задавала, но без них три реализации разъехались бы. Всё общее
живёт в `AccessGate` и `RoleSync`, платформам решать нечего.

- **Мастер недоступен → вход закрыт.** Настоящая граница доступа — «есть
  аккаунт на мастере», и пускать всех подряд, пока мастер лежит, значит эту
  границу снять. Переключается `deny-on-master-error=false` — осознанно, ценой
  того, что на это время войдут и те, кого мастер бы не пустил.
- **404 от мастера → тоже отказ.** Игрока нет в базе — значит аккаунта нет.
- **Группа `default` неприкосновенна.** LuckPerms выдаёт её неявно, и снести
  её как «лишнюю» — тихо отобрать у всех базовые права.
- **Агент трогает только постоянные группы в глобальном контексте.** Временная
  выдача (донат на месяц) и привязка к миру приходят не от мастера, снимать их
  он не вправе.
- **Префикс группы агент держит целиком:** перед записью чистит prefix-узлы.
  Иначе смена цвета на сайте оставила бы в чате две иконки рядом.
- **На Fabric и NeoForge отказ приходит после входа в мир.** Пред-логин хука
  без микширования там нет, а тащить микшины в агент — цена выше пользы. Это
  ровно тот случай, когда проверку надо ставить на прокси.
- **Fabric-модуль — `DedicatedServerModInitializer`,** а не общий
  `ModInitializer`: агенту нечего делать на клиенте.

### Про скины — прочитать до того, как писать код

На online-mode сервере с authlib-injector текстуры приходят из профиля
Yggdrasil сами, и агенту делать нечего. `skin_url` и `cape_url` в API нужны
только для случаев, где профиль не долетает: бэкенды в offline-mode за прокси
без forwarding, или интеграция со SkinsRestorer.

Не писать синхронизацию скинов «на всякий случай» — сначала проверить, нужна
ли она в текущей конфигурации.

**Не написана.** Проверка не проводилась, повода не возникло: `skin_url` и
`cape_url` разбираются в модель и лежат готовыми, а синхронизация появится
тогда, когда найдётся конфигурация, где профиль не долетает.

### ServerWrapper

Это **установщик и супервизор, а не охрана**. Авторизацию делегировать ему
нельзя — она на мастере, и там ей место.

- определяет платформу и версию по jar-файлу сервера;
- ставит и обновляет нужный агент;
- прокидывает `-javaagent` с authlib-injector и корнем `/api/yggdrasil`;
- держит секрет в одном месте, агент читает его оттуда;
- шлёт heartbeat, пока сервер ещё грузится.

Раздачу jar'ов агента надо подписывать тем же ed25519, которым подписываются
манифесты сборок, и проверять подпись во враппере. Это защита канала доставки,
и она работает по-настоящему — в отличие от попыток подтвердить, какой клиент
у игрока.

## Чего обещать нельзя

**«На сервер пускает только с моим лаунчером» — недостижимо.** Ключи
подтверждают происхождение файла, а не то, какая программа сейчас в памяти.
Любую проверку на стороне клиента атакующий воспроизводит: код исполняется на
его машине. У GravitLauncher та же дыра под обфускацией.

Что есть на самом деле: `/authserver/authenticate` не смонтирован, пароля нет,
токен добывается только через Discord OAuth. Это отсекает ленивый путь, но
повторить OAuth-флоу с локальным слушателем и скормить токен стороннему
клиенту может любой, кто разберётся. Реальная граница — «есть аккаунт на
мастере», и строить защиту надо на ней.

## Решённые вопросы

- **Раздача jar'ов агента.** Сделан `GET /api/agent/artifact` (см. выше).
  Админ кладёт собранный jar в `{NORO_DATA_DIR}/agents/`, дальше работает
  существующий стор. Отдельная таблица не заводилась: имя файла и есть ключ.
- **Bootstrap Gradle.** Ставить ничего не пришлось: в `~/.gradle/wrapper/dists`
  уже лежали дистрибутивы, и `gradle-9.6.1` сгенерировал wrapper, который
  теперь в репозитории. `brew install gradle` не нужен.
- **JDK 21.** Java 26 в системе не единственная — рядом стоит Temurin 21,
  toolchain находит его сам. Ловушка в обратную сторону: **сам Gradle нельзя
  запускать на 26**, поэтому перед `./gradlew` нужен
  `export JAVA_HOME=$(/usr/libexec/java_home -v 21)` либо раскомментированный
  `org.gradle.java.home` в `gradle.properties`.
- **Тестовый стенд.** Отдельный стенд не понадобился для того, что проверяемо
  без игры: разбор ответа мастера, раскладка ролей, формат префикса и подпись
  артефакта закрыты юнит-тестами (`./gradlew test`, 22 теста). Мастер для
  живых прогонов поднимается второй копией на другом порту с той же БД —
  `NORO_BIND=127.0.0.1:18080 ./target/debug/noro-master`, — так основной
  инстанс не трогается.

## Что проверено на живом сервере

NeoForge 1.21.1, сборка из 146 модов, запуск через ServerWrapper. Прошло всё:
определение платформы и версии, установка агента с проверкой подписи, подстановка
`-javaagent`, старт сервера и heartbeat. В `game_servers` приехало
`version = "NeoForge 1.21.1"`, `max_online = 20`, `last_seen_at` — то есть
сработала и ветка `//#else` препроцессора в `ModServerStatus`.

## Что осталось непроверенным вживую

Всё, что требует входа игрока: раскладка групп через настоящий LuckPerms,
отказ во входе, префиксы в чате. Код против этих API компилируется и грузится,
но поведение при подключении не наблюдалось.

Туда же — вся выдача прав: что обработчик действительно становится активным
после правки `permissionHandler`, что `PlayerNegotiationEvent` успевает раньше
`sendCommands`, что мод видит право и что `PermissionAttachment` на Paper даёт
ожидаемое. Сигнатуры сверены с jar'ами 1.18.2 → 1.21.11 и всё компилируется на
всех 80 сборках, но живого сервера под этим не было.

## Сборка

```bash
export JAVA_HOME=$(/usr/libexec/java_home -v 21)
cd agent && ./gradlew collectAgents
```

`collectAgents` складывает всё в `agent/build/agents/` под именами, которые ждёт
`GET /api/agent/artifact`, — каталог остаётся скопировать в `{NORO_DATA_DIR}/agents/`:

```
paper-1.21.1.jar  fabric-1.21.1.jar  fabric-1.21.4.jar
                  neoforge-1.21.1.jar  neoforge-1.21.4.jar
```

Враппер собирается отдельно: `wrapper/build/libs/wrapper-0.1.0.jar`, конфиг —
`wrapper/noro-wrapper.properties.example`.

Классы `core` вложены в каждый jar: runtime-зависимостей у него нет, поэтому
shadow и релокация не понадобились.

### Мультиверсионность

`./gradlew collectAgents` собирает **80 агентов** в `agent/build/agents/` под
именами `{platform}-{mc}.jar` — ровно то, что ждёт `GET /api/agent/artifact`.

| Лоадер | Версий | Диапазон |
|---|---|---|
| Paper | 26 | 1.18.2 → 26.2 |
| Fabric | 30 | 1.18 → 26.2 |
| NeoForge | 16 | 1.20.2 → 1.21.11 |
| Forge | 8 | 1.18.2 → 1.20.1 |

Fabric, NeoForge и Forge собираются из **одного** исходника в `mod/src/main/java`
препроцессором ReplayMod через `essential-gradle-toolkit`. Официальный
`maven.replaymod.com` недоступен — всё тянется с зеркала `repo.essential.gg`,
оно же отдаёт форк loom, на котором toolkit работает.

Мэппинги у всех узлов `official` (Mojang), поэтому переименовывать идентификаторы
между yarn и mojmap не нужно — остаётся только обработка `//#if`. Директив в коде
**две**: три точки входа закрыты целиком (`FabricEntry`, `NeoForgeEntry`,
`ForgeEntry`) плюс `Component.literal` (появился в 1.19) и строка версии в
`ModServerStatus`. Вся логика — в общем `AgentRuntime`, без единой директивы.

Paper препроцессора не требует: Bukkit API для нужных агенту вызовов не менялся
с 1.18, расходится только координата `paper-api`.

**Добавить версию** — создать каталог `mod/versions/<mc>-<loader>/` или
`paper/versions/<mc>/`. Граф препроцессора и `settings.gradle.kts` выводятся из
каталогов, списка для ручной правки нет нигде.

### Метаданные мода разведены по лоадерам

`mod/src/{fabric,forge,neoforge,neoforge-legacy}/resources/` — по каталогу на
вариант, нужный подкладывается в jar задачей `jar`.

Общего файла тут быть не может: **NeoForge до 1.21 читает `META-INF/mods.toml`,
как и Forge, но зависит от `neoforge`, а не `forge`, и пишет `type=` вместо
`mandatory=`.** Один файл на обоих — это NeoForge 1.20.x, который не грузится
вовсе, потому что требует несуществующий мод `forge`. Ошибка тихая: сборка
проходит, падает только запуск сервера.

Кладутся именно в `jar`, а не в `resources`: препроцессор подменяет каталог
ресурсов своим (`build/preprocessed`), и добавленный `srcDir` туда не доезжает.

### Три требования к Java, а не одно

Minecraft дважды поднимал планку, и `paper-api` объявляет это в метаданных Gradle —
сборка под меньшую версию **не разрешается вовсе**, а не падает при компиляции.

| MC | Java |
|---|---|
| 1.18 – 1.20.4 | 17 |
| 1.20.5 – 1.21.11 | 21 |
| 26.x | 25 |

Отсюда нижняя граница диапазона: `core` использует records, а ниже 1.18 сервер
работает на Java 16/8. Поэтому **`core` и враппер собираются под Java 17**, а не
21 — иначе они не загрузились бы на серверах 1.18–1.20.4. Проверка: `major
version: 61` в их классах.

### Разрывы API, найденные сборкой

- **1.19** — появился `Component.literal`, до него `TextComponent`. Закрыто `//#if`.
- **1.21.9** — `GameProfile` стал record: `getName()` → `name()`. Директивой не
  закрывали, перешли на `getScoreboardName()` — он одинаков на всём диапазоне.
- **1.21.9** — удалён `ServerPlayer.getServer()`. `MinecraftServer` теперь
  запоминается на старте сервера.
- **Forge** — `PlayerEvent.getPlayer()` исчез в 1.19, но `getEntity()` объявлен
  ещё в `EntityEvent` и работает на всём форджевом диапазоне. Директива не нужна.

### MC 26.x собирается иначе

С `mcVersion >= 260000` toolkit применяет `LoomNoRemapGradlePlugin`: игра
необфусцирована, ремапить нечего. В таких проектах **нет** конфигураций
`mappings`, `modImplementation` и `neoForge` — есть `minecraft` и обычный
`implementation`. Задачи `remapJar` там тоже нет, итоговый артефакт даёт `jar`.

Из-за отсутствия `neoForge` объявить платформу NeoForge под 26.x нечем —
**NeoForge 26.x этим путём не собирается**. Fabric и Paper 26.x собраны.

### Чего в матрице нет

- **NeoForge ниже 1.20.2** — его тогда не существовало, там Forge.
- **NeoForge 1.20.3** — падает на remap Minecraft. MC 1.20.3 прожила четыре дня
  и заменена 1.20.4; Fabric и Paper под неё есть.
- **NeoForge 26.x** — см. выше.
- **Fabric 1.18.1** — под неё не выпущен `fabric-api`.
- **Paper 1.21.2** — Paper эту версию пропустил.

Часть веток NeoForge (1.20.5, 1.21.2, 1.21.6, 1.21.7, 1.21.9) существует только
в beta — они взяты, иначе у этих версий не было бы агента вовсе.

Paper 1.20.5 требует локальной заплатки: его `paper-api` импортирует
`net.kyori:adventure-bom:4.17.0-SNAPSHOT`, а снапшот удалён отовсюду, и без него
не разбирается сам POM. `resolutionStrategy` и `dependencySubstitution` не
помогают — они срабатывают после разбора метаданных. Поэтому в
`paper/versions/1.20.5/local-repo/` лежит POM релиза 4.17.0 с заменённой строкой
версии.

### Публичный ключ подписи

`GET /api/agent/pubkey` отдаёт ключ мастера, чтобы не разносить его руками по
серверам. Враппер берёт его **один раз** и запоминает в `noro/signing-key.pub`;
дальше сверяет только с запомненным, расхождение — жёсткий отказ.

Ключ, взятый по тому же каналу, что и артефакт, не защитит от подмены этого
канала — но подменить его можно только при первой установке, а не в любой момент
потом. Явно заданный в конфиге `signing-public-key` — настоящий якорь и всегда

## Правила репозитория

Действуют из `CLAUDE.md`: **≤150 строк на файл**, один компонент — один файл,
