# Резервная копия мастера: архив, подпись, восстановление

Сделано. Раньше был только `GET /api/admin/backup` — поток `pg_dump`: без файлов
данных, без восстановления и без способа проверить, что скачанное не подменено.
Ручка осталась как быстрый способ забрать одну базу; всё остальное — ниже.

Код: `crates/master/src/backup/`, ручки в `api/admin/backup.rs` и
`api/admin/backup_restore.rs`, страница `web/pages/admin/backup.vue`.

## Архив

`noro-backup-{дата}.tar.gz`:

```
dump.sql       pg_dump всей базы (plain)
data/          содержимое NORO_DATA_DIR: сборки, скины, плащи, агенты
meta.json      версия мастера, версия схемы, дата, размеры, sha256 частей
signature      Ed25519 по sha256(meta.json)
```

**Порядок записей обратный оглавлению.** `meta.json` держит sha256 остальных
частей, поэтому пишется последним: пока файлы не прочитаны, их хеши неизвестны.
Побочный выигрыш — оборванная закачка отвергается сама собой: у обрезанного
архива нет паспорта.

Ничего не складывается на диск целиком: архив собирается на лету и стримится в
ответ. Во временный файл ложится только `dump.sql` — размер записи tar стоит в
заголовке, а у потока `pg_dump` его взять неоткуда.

**Версия схемы обязательна.** `MAX(version)` из миграций, зашитых в бинарник
(`db::known_schema_version`). Дамп со схемой 62 нельзя лить в бинарник, который
знает 58: миграции вперёд не откатываются.

**Подпись — тем же ключом, что и манифест** (`NORO_SIGNING_KEY`). Отдельный ключ
незачем: кто может подменить манифест, тот и так владеет мастером. Подписывается
`meta.json`, а он держит sha256 остальных частей — одной проверкой закрывается
весь архив. Без ключа архив собирается **без** подписи и помечается
`signed: false` в паспорте; админка это показывает отдельной строкой.

## Восстановление

`POST /api/admin/backup/restore`, право отдельное — `noro.admin.backup.restore`.
Суффиксный wildcard требует `.*`, поэтому `noro.admin.backup` его не покрывает и
выдавать его нужно явно.

Разбор отделён от применения: `POST /api/admin/backup/inspect` кладёт загрузку в
служебный каталог и возвращает её id вместе с вердиктом, `restore` берёт файл по
id. Заливать гигабайты дважды ради одного подтверждения незачем. Вердикт при этом
ничего не разрешает — `restore` проверяет архив заново.

Порядок, каждый шаг с отказом до того, как что-то тронуто:

1. подпись и sha256 частей — не сошлось, отказ;
2. версия схемы: архив новее бинарника — отказ с обеими версиями в тексте;
3. `data/` разворачивается в staging целиком, затем содержимое тома меняется
   местами; прежнее уезжает в `.noro-backup/old-{дата}`;
4. БД: обрыв чужих соединений, очистка схемы, заливка дампа;
5. запись в аудит (`backup.restore`) — после заливки, иначе строка исчезла бы
   вместе с прежним журналом.

### Развилка про БД: решена самовыходом процесса

Мастер отвечает и через две секунды выходит с кодом 0; `restart: unless-stopped`
поднимает его уже на восстановленных данных. «Восстановить на живой» не бывает:
пул смотрит в таблицы, которых после заливки нет, а кэши в памяти помнят прежнюю
базу.

`MaintenanceStart` из первоначального плана для этого не годился — он шлёт кик
игровым агентам и на собственный пул мастера не влияет.

### Две вещи, вскрывшиеся на проверке

**Том нельзя переименовать.** `NORO_DATA_DIR` на проде — точка монтирования
(`noro-data:/app/data`), `rename` на ней отвечает `EBUSY`. Поэтому меняется
содержимое, а не каталог: staging и `old-{дата}` лежат в `.noro-backup/` внутри
тома, все переносы идут по одной файловой системе.

**Одного `--clean` мало.** Дамп снимает только те объекты, что в нём есть.
Восстановление архива постарее оставило бы таблицы от более поздних миграций и
одновременно откатило бы `_sqlx_migrations` — на старте мастер накатывал бы их
повторно и падал на «relation already exists». Проверено на схеме из 62 миграций:
посторонняя таблица переживает восстановление. Поэтому перед заливкой идёт
`DROP SCHEMA public CASCADE; CREATE SCHEMA public`, а `pgcrypto` возвращается из
самого дампа. Чужие соединения перед этим обрываются, иначе `DROP SCHEMA` ждал бы
блокировку; `lock_timeout` даёт упереться и отказать, а не висеть.

## Админка

`/admin/backup`: выгрузка дампа, сборка полного архива со счётчиком принятого и
восстановление. Загрузка идёт через XHR — прогресса отдачи тела у `fetch` нет.
Скачивание пишет прямо на диск через `showSaveFilePicker`, если браузер умеет:
собирать многогигабайтный архив в памяти вкладки значит её уронить.

Перед подтверждением показывается разбор паспорта: дата, версия мастера, версии
схемы (архива и мастера), размер, число файлов и состояние подписи — отдельно
«не сходится» и «архив без подписи». Причину отказа считает мастер, админка её не
дублирует.

## Что покрыто тестами

`backup/tests.rs` — сборка и проверка архива: честный архив, чужой ключ,
неподписанный архив, подмена содержимого при целой подписи, архив новее
бинарника. `backup/swap_tests.rs` — подмена содержимого тома, сохранность
служебного каталога, уборка загрузок и отсев путей вида `data/../../etc/passwd`.

Связка `pg_dump` → `psql` проверена руками на реальной схеме из 62 миграций, в
том числе под шестнадцатью живыми соединениями.
